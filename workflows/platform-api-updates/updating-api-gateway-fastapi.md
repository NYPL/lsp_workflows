# `fastapi` and `aws-cli` workflow
If your app is a python app developed using `fastapi`, leverage the open api json generator. 

## Steps:
### 1. Extract openapi json
Run a script like the AI-generated (Gemini webapp) script `./extract_openapi.py` for reference. This script is for use with an app deployed as a lambda. Update the `LAMBDA_FUNCTION_NAME` to the lambda you want to connect to the API gateway. The script will output a JSON file documenting the OpenAPI spec generated by fast api. This JSON will be pushed to API gateway in the next step.

Note: If you want the endpoints to point to the correct environment per stage, for now you will have to manually update the JSON file. add `${stageVariables.environment}` to the `uri` property in `x-amazon-apigateway-integration`. This is because OpenAPI validation prohibits curly braces. 
For example:
```
        "x-amazon-apigateway-integration": {
          "type": "aws_proxy",
          "httpMethod": "POST",
          "uri": "arn:aws:apigateway:us-east-1:lambda:path/2015-03-31/functions/arn:aws:lambda:us-east-1:946183545209:function:ListsService-${stageVariables.environment}/invocations",
          "passthroughBehavior": "when_no_match"
        }
```

### 2. PUT the changes to the API Gateway
The procedure outlined below will update the API Gate way using `merge` mode. It will only update the API Gateway, it will not overwrite the entire thing. However, there is a risk of overwriting an existing, functional endpoint. In the example command, `PATH_TO_OPENAPI.JSON` should be the path to the JSON output in the previous step.
- ensure aws is authenticated
- check that you are not overwriting the API Gateway name via the open api json file
- verify that you are not, e.g., overwriting the bib service endpoint
- run the following command:

```
aws apigateway put-rest-api  \
    --rest-api-id {API GATEWAY ID} \
    --mode merge \
    --body file://{PATH_TO_OPENAPI.JSON} \
    --cli-binary-format raw-in-base64-out
```
